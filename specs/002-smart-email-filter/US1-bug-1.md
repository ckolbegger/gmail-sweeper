# Bug: Error message not displayed when AI configuration is missing

**Status:** ✅ FIXED in commit 3bdf95f

**Found by:** tui-exploratory-tester (manual execution)
**Target:** US1 — Filter Inbox by Natural Language Description
**Discovery:** Exploratory testing — missing AI configuration error handling
**Severity:** major

## Summary

When the AI provider is not configured (AI_PROVIDER, AI_MODEL, AI_API_KEY missing from environment), submitting a filter query fails silently. The error message is generated by the `useSmartFilter` hook but is never displayed to the user. Instead, the app returns to the email list view as if nothing happened.

## Steps to Reproduce

1. Ensure `.env` does NOT have AI configuration:

   ```
   # AI_PROVIDER=anthropic
   # AI_MODEL=claude-sonnet-4-5-20250929
   # AI_API_KEY=your_key_here
   ```

2. Start the app: `npm run dev`

3. Press `f` to activate smart filter

4. Type any filter description (e.g., "invitations to events")

5. Press Enter to submit

## Expected Behavior

The app should display an error message explaining that AI configuration is missing:

> "AI configuration is missing. Please set AI_PROVIDER, AI_MODEL, and AI_API_KEY environment variables."

The user should see this error in the filter input area and be able to dismiss it with Escape.

## Actual Behavior

The app silently returns to the email list view. No error message is displayed. The filter is not applied. The user has no indication of what went wrong.

## Root Cause Analysis

In `src/cli/app.tsx` (lines 269-282), the `FilterInput` component is only rendered when `smartFilter.state` is `'input'` or `'loading'`:

```typescript
// Line 269
smartFilter.state === 'input' || smartFilter.state === 'loading'
  ? React.createElement(FilterInput, {...})
  : React.createElement(Box, {...}, /* email list */)
```

When the AI configuration is missing:

1. `submitFilter()` calls `createProviderFromConfig()` which throws an error
2. The catch block sets `state` to `'error'` and `error` to the error message
3. Since state is now `'error'` (not `'input'` or `'loading'`), the app renders the email list
4. The `FilterInput` component (which can display errors) is not rendered
5. The error message exists in state but is never visible to the user

## Relevant Files

- `src/cli/app.tsx` — Lines 269-282: Conditional rendering logic
- `src/cli/hooks/use-smart-filter.ts` — Lines 45-68: Error state management
- `src/cli/components/filter-input.tsx` — Lines 50-54: Error display capability

## Suggested Fix

Modify the conditional rendering in `app.tsx` to also show `FilterInput` when state is `'error'`:

```typescript
smartFilter.state === 'input' || smartFilter.state === 'loading' || smartFilter.state === 'error'
  ? React.createElement(FilterInput, {
      onSubmit: (description) => smartFilter.submitFilter(description),
      isLoading: smartFilter.state === 'loading',
      error: smartFilter.error,
    })
  : React.createElement(Box, {...}, /* email list */)
```

Alternatively, render a dedicated error component when state is `'error'`.

## Test Coverage

This bug is NOT caught by the existing unit tests because:

- The `useSmartFilter` hook tests verify that error state is set correctly
- The integration tests mock the AI provider (so no error occurs)
- The app component integration tests don't test the error state UI

A new test should be added to `tests/unit/cli/app.smart-filter.test.tsx` to verify error display when AI is not configured.

## Additional Exploratory Testing Results

The following inputs all trigger the same silent failure:

- Empty filter (just pressing Enter)
- Single character filter ("a")
- Spaces-only filter (" ")
- Very long filter description (100+ characters)
- Special characters in filter

All of these should show the configuration error message, but none do.
